Classroom Activities and Exercises

All hands-on exercises this semester were done in Oracle APEX and SQL Developer Data Modeler. They are documented in full in the Laboratory Activities section below, in the order I did them.

Laboratory Activities

Arranged from first to most recent. Tools: SQL Developer Data Modeler and Oracle APEX SQL Commands.

Prelim

Prelim Activity No. 1 – Conceptual Model Using SQL Data Modeler

Task: Build a conceptual ERD of an HR-style database.

Output: Entities EMPLOYEE, DEPARTMENT, JOB, LOCATION, COUNTRY, and REGION, with the relationships between them, including EMPLOYEE’s relationship to itself.

Explanation: This was my first step in turning a business description into entities, attributes, and relationships before writing any SQL.

Prelim Activity No. 2 – Super Type / Sub Type Entities

Task: Model the OBL Store database with a supertype and subtype, then generate the relational model.

Output: A logical model with SALES_REP, TEAM, ORDER, ORDER_ITEM, PRODUCT, and INDIVIDUAL_CUSTOMER, plus its relational version showing the keys.

Explanation: I practiced how a logical model becomes tables with primary and foreign keys. I also learned how supertype and subtype entities are represented.

Midterm

Midterm Assignment No. 1 – Oracle APEX Account

Output: Screenshot of my Oracle APEX workspace and profile, showing a working account.

Explanation: This set up the environment I used for every SQL activity afterward.

Midterm Activity No. 1 – Creating Tables

Output: CREATE TABLE for DEPT and EMPLOYEES, with DESCRIBE results.

Explanation: I used a primary key, NOT NULL, a UNIQUE email, a CHECK constraint on hire date, and a DEFAULT SYSDATE value. The Describe output confirmed each column and constraint.

Midterm Activity No. 2 – Inserting Records

Explanation: I added rows to tables using INSERT INTO and checked them with SELECT. Screenshots are in the original document submitted for this activity.

Midterm Activity No. 3 – Modifying and Updating Records

Output: ALTER TABLE to add columns, UPDATE on department IDs, locations, and manager IDs, then a SELECT to verify.

Explanation: The updates changed existing rows in COPY_EMPLOYEES and COPY_DEPT without recreating the tables. I used WHERE so only the intended rows changed.

Final Term

Final Term Activity No. 1 – Arithmetic and Concatenation Operators

Output: A query adding 300 to salary, a computed annual salary (salary * 12), an UPDATE setting commission to 10% of salary, and concatenated text such as “is a” with column aliases.

Explanation: Arithmetic operators compute new values inside a query. The concatenation operator || joins columns and text into readable output, and aliases give the columns clear names.

Final Term Activity No. 2 – Filtering, Aggregate Functions, and Joins (Activities 10–12)

Output:

Activity 10: created TB_DOCSTATUS and TB_STATUS, then ran INSERT, UPDATE, and DELETE.

Activity 11: used IS NULL, LIKE, DISTINCT, ORDER BY with FETCH FIRST, and AVG, SUM, MIN, MAX, and COUNT.

Activity 12: used aggregates on salaries, and NATURAL JOIN, JOIN … USING, and JOIN … ON to combine employees with departments.

Explanation: All three join types gave the same employee and department pairing. One query returned “no data found” because 'MANAGER' did not match the stored value 'Manager', so I learned that text comparisons are case-sensitive.

Final Term Activity No. 3 – SQL Sorting and Joining Tables, Part 2 (Problems 1–15)

Output: Fifteen problems on TB_EMPLOYEE and TB_DEPARTMENT: multi-column ORDER BY, filtering by salary and hire date, full-name concatenation, a CASE-based ordering by position, inner joins, GROUP BY with HAVING, and subqueries comparing salary to department and company averages.

Explanation: Each problem has its query and result screenshot in the submitted PDF. Problem 14 returned no data, which meant no rows met its conditions.

Learning Reflection

What I learned. I learned how a database is planned and then built. I started by drawing ERDs and normalizing them, then created tables with keys and constraints in Oracle APEX. I practiced inserting, updating, and deleting records, and querying data with filters, sorting, aggregate functions, and joins.

What was most challenging. Joins and subqueries were the hardest. Choosing which tables to join, and comparing each employee’s salary against a department or company average, took the most attempts. Small details such as letter case in text values also caused queries to return no data.

How I overcame it. I ran queries step by step, checked the results of each part, and compared the table contents with what my condition expected. Finishing the activities in order helped, because each one used skills from the one before.

How I will apply it. I can design and create a database for a small system, keep its data accurate, and retrieve useful information from it. These skills will help in my future IT subjects and in any project that needs to store and use data.
